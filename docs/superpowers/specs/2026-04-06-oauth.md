# AT Protocol OAuth Spec

**Date:** 2026-04-06
**Issue:** Chainlink #15
**Status:** Approved

---

## Overview

AT Protocol OAuth enables users to sign in with their Atmosphere account. After auth, we get their DID and can make authenticated API calls (crawl social graph, read follows' posts, publish recommendations). Uses OAuth 2.0 with PKCE + DPoP, resolved per-user against their PDS.

**Dev infrastructure:**
- `cimd-service.fly.dev` hosts the client metadata document
- Tailscale Funnel exposes the dev server for OAuth callbacks
- In-memory stores for session/state (dev only)

---

## 1. Dev Setup (One-Time)

1. Start Next.js dev server on port 3000
2. Run `tailscale funnel 3000` → note the public URL (e.g., `https://macmini.tail1234.ts.net`)
3. POST client metadata to `https://cimd-service.fly.dev/clients`:

```json
{
  "client_name": "Understory (Development)",
  "redirect_uris": ["https://<funnel-url>/oauth/callback"],
  "grant_types": ["authorization_code", "refresh_token"],
  "response_types": ["code"],
  "scope": "atproto transition:generic",
  "application_type": "web",
  "dpop_bound_access_tokens": true,
  "token_endpoint_auth_method": "none"
}
```

4. Response includes a `client_id` URL. Store in `.env`:

```
NEXT_PUBLIC_URL=https://<funnel-url>
OAUTH_CLIENT_ID=https://cimd-service.fly.dev/clients/<cid>
```

Public client (`token_endpoint_auth_method: "none"`) — no private keys needed in dev. Production will use `private_key_jwt` with an ES256 key.

## 3. OAuth Client Singleton

**File:** `src/lib/auth/client.ts`

Creates a `NodeOAuthClient` instance cached on `globalThis` (survives Next.js hot reload).

**Initialization:** `new NodeOAuthClient({ clientMetadata: { client_id: OAUTH_CLIENT_ID, ... }, stateStore, sessionStore })`. The `client_id` URL points to cimd-service, which hosts the metadata. The SDK fetches it to get redirect URIs, scopes, etc.

**Store interfaces:** Both stores must implement `{ get(key): Promise<T | undefined>, set(key, value): Promise<void>, del(key): Promise<void> }`. Wrap in-memory `Map` objects with these methods.

**State store** (in-memory, keyed by state string): holds in-flight OAuth flows. TTL ~10 minutes.

**Session store** (in-memory, keyed by DID): holds authenticated sessions with refresh tokens. Lost on server restart — user re-auths.

**globalThis caching:** Use `globalThis.__oauthClient ??= new NodeOAuthClient(...)` with a TypeScript global augmentation to survive Next.js hot reload.

## 4. Route Handlers

### `POST /oauth/login`

- Accepts: `{ handle: string }` in request body
- Calls `client.authorize(handle)` — SDK resolves handle → DID → PDS, does PAR, returns redirect URL
- Returns: `{ redirect: string }` — the PDS authorization URL

### `GET /oauth/callback`

- PDS redirects here with `code`, `state`, `iss` query params
- Extracts params via `new URL(request.url).searchParams`
- If params contain `error`, redirects to `/?error=auth_denied`
- Calls `client.callback(params)` — SDK exchanges code for tokens (PKCE + DPoP)
- Returns `{ session }` with `session.did` (the authenticated user's DID)
- Sets httpOnly cookie `understory_did` with the DID value, `maxAge: 7 * 86400` (7 days), `secure: true`, `sameSite: 'lax'`, `path: '/'`
- Fetches user profile to get handle via `new Agent(session).getProfile()`
- Redirects to `/for/${handle}`. If profile fetch fails, redirects to `/` as fallback.
- Note: `/for/[handle]` route does not exist yet — it will 404 until the personalized feed page (#12) is built. This is acceptable; the auth flow is functional and the cookie is set.

### `POST /oauth/logout`

- Reads DID from cookie
- Calls session revocation if available
- Clears `understory_did` cookie
- Redirects to `/`

## 5. Session Helper

**File:** `src/lib/auth/session.ts`

Exports `getSession()`:
- Reads `understory_did` cookie from request
- If present, calls `client.restore(did)` → returns `{ agent: Agent, did: string }` or `null`
- If restore fails (expired, revoked), returns `null`
- The returned `Agent` is what downstream features use for API calls

Exports `getSessionDid()`:
- Lightweight version — just reads the cookie, returns DID string or null
- For pages that need to know auth state but don't need an Agent

## 6. UI Changes

### Nav Component

- **Pre-auth:** "Sign in with your Atmosphere Account" is a `<button>` that opens a login form
- **Post-auth:** shows user avatar + handle, with a logout button
- Nav accepts auth state via props (server component passes it down)

### Login Form

- `src/components/login-form.tsx` — **must have `"use client"` directive** (uses `fetch` + `window.location`)
- Simple inline form in the Nav or a dropdown: text input for handle, submit button
- On submit: `fetch('/oauth/login', { method: 'POST', body: JSON.stringify({ handle }) })` → parse JSON → `window.location.href = response.redirect`
- This is NOT a traditional form submission — it uses `fetch` because the route returns JSON, not an HTTP redirect
- Shows loading state while the redirect is being prepared
- Shows error message if the handle is invalid (400 response from `/oauth/login`)

### Post-Auth Nav

- User avatar (from profile data) + display name or handle
- Dropdown or button for logout (POST to `/oauth/logout`)
- Nav `minimal` prop still works (hides Feed/Map on landing)

## 7. Auth State in Pages

Server components can call `getSessionDid()` to check auth state and pass it to client components. The Nav renders differently based on whether a DID is present.

For pages that need authenticated API access (future: feed, map), they call `getSession()` to get an Agent.

Cookie: `understory_did`, httpOnly, secure, sameSite=lax, path=/

## 10. Error Handling

- **Invalid handle:** `/oauth/login` returns 400 with error message. Login form shows it.
- **Auth denied:** PDS redirects to callback with `error` param. Callback redirects to `/?error=auth_denied`. Landing page can optionally read this query param to show a message.
- **Session expired:** `getSession()` returns null. Pages fall back to pre-auth state.
- **cimd-service down:** OAuth won't work. App still functions for browsing talks (pre-auth pages work fine).
