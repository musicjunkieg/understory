# Talk Page Spec

**Date:** 2026-04-06
**Issues:** Chainlink #6, #7, #8, #9
**Status:** Approved

## Overview

The talk page (`/talk/[rkey]`) is the core content experience for Understory. It displays an ATmosphereConf talk with HLS video playback, a synchronized scrolling transcript with click-to-seek, and in-transcript search. The page is statically generated from local data files.

---

## 1. Page Layout

**Route:** `/talk/[rkey]` — dynamic route, statically generated via `generateStaticParams`.

### Structure (top to bottom)

1. **Top Nav** — existing `Nav` component (misty glass, fixed)
2. **Header** — full-width, below nav
   - Talk title: `headline-md` (Newsreader)
   - Speakers: `label-md` (Space Grotesk) — "Speaker Name @handle" for each
   - Metadata chips: room, talk type, formatted duration — using `Chip` component
   - Description: `body-md` (Work Sans), `on-surface-variant` color
3. **Content Split** — two-column layout below header
   - **Left column (~60%)**: HLS video player, sticky-positioned
   - **Right column (~40%)**: Transcript panel with search, scrollable

### Responsive

- Desktop (>1024px): side-by-side video + transcript
- Tablet/Mobile (<=1024px): stacks vertically — header → video (not sticky) → transcript

## 2. Data Loading

### Sources

| Data | File | Shape |
|------|------|-------|
| Talk metadata | `data/talks.json` | Array of `TalkEntry` objects (see `scripts/build-talk-index.ts`) |
| Transcript | `data/transcripts/[rkey].json` | `{ uri, cid, title, creator, duration, createdAt, transcription: { id, status, text, utterances, words, audio_duration } }` |

### Utterance Shape

These interfaces are the subset needed for the talk page. The full transcript JSON also has `confidence` on both utterances and words (not used in the UI).

```ts
interface Utterance {
  speaker: string;       // "A", "B", "C"
  text: string;          // Full utterance text
  start: number;         // Start time in ms
  end: number;           // End time in ms
  words: Word[];         // Word-level timing
  confidence?: number;   // 0-1 (not displayed)
}

interface Word {
  text: string;
  start: number;         // Start time in ms
  end: number;           // End time in ms
  speaker: string;
  confidence?: number;   // 0-1 (not displayed)
}
```

### Static Generation

- `generateStaticParams`: reads `data/talks.json`, returns `{ rkey }` for each talk with a `transcriptFile`
- Page component: reads talk entry from `talks.json` by rkey, reads transcript file, passes both as props to client components

## 3. HLS Video Player (Issue #7)

### Dependencies

- `hls.js` — HLS adaptive streaming library

### Component: `VideoPlayer`

**Props:**
- `hlsUrl: string` — HLS playlist URL
- `onTimeUpdate: (timeMs: number) => void` — callback with current playback position in ms
- `seekTo: { timeMs: number; id: number } | null` — when set, seeks the video to `timeMs`. The `id` is an incrementing counter so re-clicking the same segment triggers a new seek.

**Behavior:**
- Initializes HLS.js, attaches to a `<video>` element
- Native `<video>` controls (no custom controls for now — simpler, accessible, functional)
- Fires `onTimeUpdate` on the video's `timeupdate` event (~4x/sec)
- When `seekTo.id` changes, seeks the video to `seekTo.timeMs`
- Falls back to native HLS on Safari (no hls.js needed)
- Player container: `rounded-lg overflow-hidden` with `surface-container-lowest` background

**Sticky behavior (desktop only):**
- `position: sticky; top: 5rem` (below the fixed nav)
- `self-start` to prevent stretching in the flex layout

## 4. Transcript Panel (Issue #8)

### Sentence Splitting

Utterances are split into sentence-level segments for better click-to-seek precision:

1. Split utterance `text` on sentence boundaries: `/(?<=[.!?])\s+/`
2. Walk the utterance's `words` array sequentially with a pointer. For each sentence:
   a. Split the sentence into tokens on whitespace
   b. Match tokens against consecutive words starting from the current pointer position. Strip trailing punctuation from both sides for comparison (e.g., `"it's,"` → `"it's"`).
   c. Record the first matched word's `start` as the segment's `startMs`
   d. Record the last matched word's `end` as the segment's `endMs`
   e. Advance the pointer past all consumed words
3. If word matching fails for a sentence (e.g., text normalization differences), fall back to interpolating the time range proportionally based on character offset within the utterance.
4. Preserve the utterance's `speaker` label

```ts
interface TranscriptSegment {
  id: string;            // "u0-s0", "u0-s1", etc.
  speaker: string;       // "A", "B"
  text: string;          // Sentence text
  startMs: number;       // Derived from word timing
  endMs: number;         // Derived from word timing
}
```

This splitting happens once at build time (in the page's server component), not at runtime.

### Component: `TranscriptPanel`

**Props:**
- `segments: TranscriptSegment[]` — pre-split sentence segments
- `currentTimeMs: number` — current video playback position
- `onSeek: (timeMs: number) => void` — callback when user clicks a segment

**Behavior:**
- Scrollable panel with `surface-container-low` background
- Height on desktop: `height: calc(100vh - 5rem)` with `overflow-y: auto` (5rem = nav height + padding). On mobile, natural flow (no fixed height).
- Each segment rendered as a row:
  - Speaker label: `body-md` **bold**, `primary-fixed-dim` color (only shown when speaker changes from previous segment). Uses resolved speaker name where possible (see Section 7), not uppercase.
  - Timestamp: `label-sm`, `on-surface-variant`, formatted as `MM:SS` — clickable
  - Text: `body-lg`, `on-surface` color
- **Active segment** (where `currentTimeMs` falls between `startMs` and `endMs`):
  - Left border: 2px `primary-fixed`
  - Background: `surface-container-high`
  - Transition: 150ms ease
- **Click-to-seek**: clicking anywhere on a segment calls `onSeek(segment.startMs)`
- **Auto-scroll**: when the active segment changes, scroll it into view using `scrollIntoView({ behavior: 'smooth', block: 'center' })`
- **Scroll lock**: if the user manually scrolls, pause auto-scroll. Resume when the user clicks a segment or presses a "resume follow" button.

### Scroll Lock Logic

- Track `userScrolled` state
- Set `userScrolled = true` on manual scroll events (distinguish from programmatic scroll)
- Set `userScrolled = false` when user clicks a segment
- Show a small "↓ Follow" button (floating, bottom-right of transcript panel) when `userScrolled` is true

## 5. Transcript Search (Issue #9)

### Component: Integrated into `TranscriptPanel`

**Behavior:**
- Search input at the top of the transcript panel
- Styled per design system: `surface-container-highest` background, `primary-fixed` focus glow
- As user types, filter segments to those containing the search term (case-insensitive)
- Highlighted matches: wrap matching text in a `<mark>` with `bg-primary-fixed/20 text-on-surface` styling
- Match count shown as `label-sm` to the right of the input: "12 matches"
- Clicking a filtered segment still triggers seek
- Empty search shows all segments (default state)
- Auto-scroll is paused while a search filter is active (the active segment may not be in the filtered results). Auto-scroll resumes when the search is cleared.

## 6. Component Architecture

```
/talk/[rkey]/page.tsx          (Server Component — data loading, sentence splitting)
  └─ TalkPageClient.tsx        (Client Component — state coordination)
       ├─ VideoPlayer.tsx       (HLS.js player, exposes time + seek)
       └─ TranscriptPanel.tsx   (Segments, search, auto-scroll, click-to-seek)
```

**State lives in `TalkPageClient`:**
- `currentTimeMs: number` — from video's timeupdate
- `seekTo: { timeMs: number; id: number } | null` — set when user clicks a transcript segment. `id` increments on each click to allow re-seeking to the same timestamp.
- `seekCounter: number` — ref that increments on each seek request

**Data flow:**
- Video → `onTimeUpdate` → `TalkPageClient` updates `currentTimeMs` → passed to `TranscriptPanel`
- Transcript click → `onSeek` → `TalkPageClient` sets `seekTo` → passed to `VideoPlayer`

## 7. Formatting Helpers

- **Duration**: `durationMs` → `"45 min"` or `"10 min"` (rounded to nearest minute). For durations under 1 minute, show `"< 1 min"`.
- **Timestamp**: `startMs` → `"MM:SS"` format
- **Speaker**: positional mapping from diarization labels to talk speaker list: "A" = `speakers[0]`, "B" = `speakers[1]`, etc. Show resolved name if available, fallback to "Speaker A". Note: this mapping is a best-effort assumption from AssemblyAI's diarization — labels are arbitrary and may not match speaker order perfectly, especially for 3+ speaker panels.
- **Date/time**: `startsAt` → formatted as "Mar 27, 4:15 PM PDT"

---

## 8. Accessibility

- Transcript segments are `<button>` elements (not clickable divs) for native keyboard support and screen reader semantics
- Each segment button has `aria-label`: "[Speaker Name], [timestamp]: [first 50 chars of text]..."
- Transcript panel has `role="region"` with `aria-label="Transcript"`
- Search input has `aria-label="Search transcript"` and the match count uses `aria-live="polite"` to announce updates
- The "Follow" button (scroll lock resume) has `aria-label="Resume auto-scroll"`
- Active segment change does NOT trigger `aria-live` announcements (too frequent, would overwhelm screen readers)

---

## 9. Error & Edge Cases

- **No transcript**: if `transcriptFile` is null, hide the transcript panel entirely. Show video full-width with metadata.
- **Invalid rkey**: Next.js `notFound()` — returns 404.
- **HLS load failure**: show error message in the video container: "Video unavailable. Try refreshing."
- **Empty search results**: show "No matches" message in transcript panel.
